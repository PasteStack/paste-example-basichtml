What Paste costs

Paste builds on the browser instead of replacing it, so the question is not whether it beats the native DOM but what it costs on top of it. Two measurements, both taken live in your browser, answer that: TaskSpeed, the classic DOM benchmark, with Paste beside the native DOM and jQuery, and what the showcase page costs to load. Nothing here is a recorded result.

Run TaskSpeed

TaskSpeed times sixteen everyday DOM jobs: build lists, bind events, set classes and styles, insert and remove elements. Each contender runs them in its own frame, starting from the same empty page. After every task, every one must return the same value and leave the same document, so none can skip work the document shows. Listeners leave no trace in a document, so the bind tasks are compared by the count each returns.

Expect the native DOM to be fastest overall: nothing runs on top of it. What the table shows is how close Paste stays to it, and how far a classic DOM library falls behind.

Runs the sixteen tasks five times in your browser, usually in a few seconds. jQuery loads only when you run it.

Lower is faster. Each cell is the task's median time and the value it returned; Total adds up a contender's medians. The fastest in each row is marked in green and bold, and times that read the same tie.

The showcase page, measured

Press the button and the showcase loads in a hidden frame; once its modules have started, its own timings say how large its Paste scripts are, uncompressed, and when they arrived, counted from the start of its navigation. These are the costs of the showcase, not of this page, measured with your browser's cache as it is: scripts you have already loaded come from the cache, and would arrive later on a first visit. A script the server first confirmed as current reads "your cache, after a check", and the browser may not report its size. How it is measured

TaskSpeed's sixteen tasks run in the order TaskSpeed set, five rounds over. The harness empties each frame's body before the first round, and the last task empties it again, so every round starts from the same empty body. Within a round each task runs once per contender, with the contenders in a new random order every time, and only the call is timed, with performance.now(). Your browser may round that clock to protect your privacy, so very short tasks read in steps of the same size. The table shows each task's median of the five rounds, so a cold start or a garbage collection that lands in one round does not decide it, and Total adds up those medians. A task that throws in any round shows "error" and marks its row as failed, and its contender's Total reads "incomplete" instead of a sum that leaves the task out.

  • Native DOM is the baseline: the platform's own interfaces and nothing else.
  • Paste is written the way Paste is meant to be used: markup built once with MarkupWriter and inserted as one fragment, listeners through paste.event, and the platform wherever Paste defers to it.
  • Paste helpers is the native code with each call that has a Paste helper swapped for it. Set beside the native column, it shows what the helpers themselves cost.
  • jQuery 3.7.1 runs TaskSpeed's own jQuery tests, using on and off for the deprecated bind and unbind, and odd() for the deprecated :odd.

After every task, in every round, the harness compares what each contender returned and the document each one left, attribute for attribute. Listeners leave no trace in a document, so the bind tasks are compared by the count each returns. A disagreement marks the row with what differed, the value, the document or both, and takes away its fastest mark; every Total that is not "incomplete" then reads "not comparable". The row keeps the values from the round where a value first differed; when only the documents differed, the values match. A document that differs after one task carries the difference into the tasks after it, until finale empties the body, so those rows are marked too. The original TaskSpeed counted against a copy of the W3C Selectors specification in each frame; here every frame starts empty, so every count is exact, and the four implementations share one definition of each task. jQuery is loaded only by its own frame, and only when you run TaskSpeed.
